\chapter{Hướng dẫn chạy và tái lập kết quả}
\label{app:run}

\section{Yêu cầu}

Docker (8 GB RAM cho VM đủ để chạy từng nhóm BR; chạy đồng thời cả bốn profile thì 8 GB không đủ, xem Mục~\ref{sec:env}), Python 3.11+, Node.js 20+. PostgreSQL mặc định ở cổng 5433 để tránh xung đột.

\section{Khởi động}

\begin{lstlisting}[language=bash]
# BR1/BR3: full stack with Kafka, Redis, PostgreSQL and separate services
docker compose -f docker-compose.yml -f docker-compose.br13.yml up -d --build

# BR4/BR5: real CDC + Spark Structured Streaming
docker compose --profile br45 up -d --build demo br45-init br45-cdc br45-stream
docker compose exec -T br45-cdc python -m edu_platform.br45.cli seed

# BR6/BR7/BR8: warehouse, content sync, live overlays
docker compose --profile br678 up -d --build     # first run takes about 4-5 minutes
docker compose exec demo edu telemetry simulate --sessions 50

# BR2: live session branch + materialise long-term features into Redis
docker compose --profile br678 run --rm --no-deps telemetry-live edu stream telemetry-live --once
docker compose run --rm spark-jobs edu batch features-online --run-date 2026-11-11

# Warehouse with synthetic data
docker compose run --rm spark-jobs edu warehouse bootstrap
docker compose run --rm spark-jobs edu warehouse seed-bronze --end-date 2026-10-17 --days 35
docker compose run --rm spark-jobs edu warehouse run --run-date 2026-10-17 --start-date 2026-08-01
docker compose exec trino trino --user analyst --catalog lakehouse
\end{lstlisting}

Mở ứng dụng tại \code{http://localhost:8000}. Overlay \code{br13} dựng các dịch vụ notification và grading trên Kafka, Redis, PostgreSQL.

Ba workspace Instructor, Advisor và Org admin yêu cầu đăng nhập bằng tài khoản nhân sự (\code{docs/STAFF_AUTH.md}). Compose mặc định không khai báo tài khoản nào (\code{EDU_STAFF_ACCOUNTS} rỗng) và chỉ khai báo một token Bearer của người học (\code{learner-demo}). Vì vậy cần tạo tài khoản và khai báo token cho script trong shell \emph{trước khi} chạy các lệnh \code{docker compose ... up} ở trên; nếu \code{demo} đang chạy thì chạy lại lệnh \code{up} đó để tạo lại container với hai biến này.

\begin{lstlisting}[language=bash]
# Staff accounts: each command asks for a password (12-128 characters)
# and prints one account with its Argon2id hash
umask 077; accounts_dir=$(mktemp -d)
.venv/bin/python -m edu_platform.br45.auth instructor instructor.demo \
  instructor-local "Demo Instructor" --course c-py-201 --course c-sql-101 \
  --course c-de-301 > "$accounts_dir/instructor.json"

  advisor-local "Demo Advisor" --course c-py-201 \
  > "$accounts_dir/advisor.json"
.venv/bin/python -m edu_platform.br45.auth admin admin.demo admin-local \
  "Demo Admin" --organisation org-acme --organisation org-globex \
  > "$accounts_dir/admin.json"
.venv/bin/python -m edu_platform.br45.auth admin acme-admin.demo \
  acme-admin-local "Acme Admin" --organisation org-acme \
  > "$accounts_dir/acme-admin.json"
export EDU_STAFF_ACCOUNTS="$(jq -cs 'add' "$accounts_dir"/*.json)"

# Bearer tokens for scripts (e2e check, BR6-BR8 benchmarks, Playwright API
# checks). Local demonstration values only: token -> identity and scope.
export EDU_BR45_AUTH='{
  "instructor-demo": {"id": "instructor-local", "role": "instructor",
    "courses": ["c-py-201", "c-sql-101", "c-de-301"]},
  "advisor-demo": {"id": "advisor-local", "role": "advisor",
    "courses": ["c-py-201"]},
  "admin-demo": {"id": "admin-local", "role": "admin",
    "organisations": ["org-acme", "org-globex"]},
  "acme-admin-demo": {"id": "acme-admin-local", "role": "admin",

Đăng nhập trên giao diện bằng tên người dùng vừa tạo (\code{instructor.demo}, \code{advisor.demo}, \code{admin.demo} cho cả hai tổ chức, \code{acme-admin.demo} chỉ cho Acme) và mật khẩu đã nhập; phiên có hạn tám giờ và mất khi API khởi động lại.

\section{Đo hiệu năng}

Các phép đo dùng stack như mục khởi động: hai tệp Compose với các profile \code{br45}, \code{br678}, \code{airflow} và \code{pipelines}, đúng như cấu hình mô tả ở Chương~\ref{chap:architecture}. Với Docker 8 GB, stack đầy đủ không chạy ổn định; trước mỗi phép đo cần tạm dừng (\code{docker compose stop}) các dịch vụ mà phép đo không dùng, theo đúng cấu hình ở Bảng~\ref{tab:env-services}, và kiểm tra không có container nào khởi động lại trong lúc đo. Năm lượt BR1--BR3 được gộp thành \code{report/data/br123_latency.csv}; các tệp kết quả còn lại được sao chép vào \code{report/data/}. Trên mã đã gộp nhánh BR4/BR5, ba lệnh \code{edu benchmark serving}, \code{content} và \code{live} gọi API bằng hai token Bearer cố định trong mã (\code{admin-demo}, \code{instructor-demo}), nên dịch vụ \code{demo} phải chạy với \code{EDU_BR45_AUTH} như ở mục khởi động.

\begin{lstlisting}[language=bash]
for i in 1 2 3 4 5; do                                  # BR1--BR3, 5 runs
  .venv/bin/python benchmarks/br123_latency.py \
    --samples 20 --br2-samples 30 \
    --out report/data/br123_latency_run$i.csv
done
.venv/bin/python -m edu_platform.br45.cli benchmark          # BR4
.venv/bin/python -m edu_platform.br45.stream_benchmark       # BR5
.venv/bin/edu benchmark serving --requests 30 \

.venv/bin/edu benchmark content \
  --out docs/evidence/br678/content_sync_latency.csv
.venv/bin/edu benchmark live --out docs/evidence/br678/live_overlay.csv
# Warehouse build: one process per (days, repeat) inside spark-jobs
docker compose run --rm -v "$PWD/docs/evidence/br678:/out" spark-jobs \
  edu benchmark marts --days 35 --repeat 1 --first-repeat 1 \
  --out /out/mart_build.csv     # repeat for 35/70/140 days, repeats 1-2

\section{Đo Debezium và polling}

Negative-control benchmark dùng bảng nguồn 100.000 dòng:

\begin{lstlisting}[language=bash]
# Generate the facts CSV if missing (deterministic, seed 42)
.venv/bin/python benchmarks/cdc/generate_facts.py \
  --rows 1000000 --output benchmarks/cdc/data/org-facts-1m.csv

# Create the source table, then the updated_at index
# (setup_source does not create the index)
.venv/bin/python -m benchmarks.cdc.setup_source \
  benchmarks/cdc/data/org-facts-1m.csv --rows 100000
docker compose exec postgres psql -U lms -d lms -c \
  "CREATE INDEX cdc_source_updated_at_idx ON bench.cdc_source (updated_at)"

# Register the Debezium connector (once)
curl -sS -X DELETE http://localhost:8083/connectors/bench-cdc >/dev/null 2>&1 || true
curl -sS -X POST -H 'Content-Type: application/json' \
  --data @benchmarks/cdc/connector.json http://localhost:8083/connectors

# Wait for the snapshot to reach 100,000 offsets
docker compose exec kafka kafka-run-class kafka.tools.GetOffsetShell \
  --broker-list localhost:9092 --topic bench.bench.cdc_source

# Run 100 UPDATEs + 10 DELETEs
.venv/bin/python -m benchmarks.cdc.run_benchmark \
  --duration 8 --updates 100 --deletes 10 \
  --out benchmarks/cdc/results/cdc_100k_indexed.json
\end{lstlisting}
